# Switching WorkOS auth from Staging to Production

`hesper login` currently uses the **Staging** WorkOS environment
(`client_01KZ1JXPJK16ADCG718H7C6VRM`, `soft-postcard-66-staging.authkit.app`).
Do this before launch, not before — Staging works fine for development.

## Why it isn't on Production already

Production was never activated: every auth method was disabled except SSO, so its
sign-in page rejected every email with *"This account is not authorized to sign in"*.
See PR #4.

## Already done (via API, 2026-08-02)

- ✅ Password, Google, GitHub auth enabled on Production
- ✅ SSO disabled
- ✅ Redirect URI set: `https://hesper-code-server.vercel.app/`

## Remaining steps

### 1. Register your own OAuth apps (the real work)

Staging borrows WorkOS's shared dev credentials for social login. Production
requires your own:

- **Google**: [Google Cloud Console](https://console.cloud.google.com) → create a
  project → OAuth consent screen → Credentials → OAuth 2.0 Client ID (type: Web
  application) → add WorkOS's callback URL (shown in the WorkOS dashboard under
  Authentication → Google) → copy Client ID + Secret into WorkOS.
- **GitHub**: GitHub → Settings → Developer settings → OAuth Apps → New OAuth App →
  same callback URL from WorkOS → copy Client ID + Secret into WorkOS.

Skip either provider you don't want to offer. Email/password needs no external setup.

### 2. Generate an API key

WorkOS dashboard → Production environment → API Keys → create one.
(`keys: []` is currently empty on the Production application.)

### 3. Optional: custom domain

Replace the autogenerated `permissible-range-10.authkit.app` with e.g.
`auth.yourdomain.com` (WorkOS dashboard → Domains; requires DNS records).
Worth doing before launch — the autogenerated domain looks untrustworthy to users.

### 4. Flip the client ID

In `apps/cli/src/auth/deviceFlow.ts`:

```ts
export const DEFAULT_WORKOS_CLIENT_ID = "client_01KZ1JXPZSYG07NQZBCPQAN46N";
```

(Production's client ID. Update the comment above it too.)

### 5. Verify before shipping

```bash
bun run --cwd apps/cli build
./apps/cli/dist/hesper.exe logout
./apps/cli/dist/hesper.exe login
```

Must print `Logged in as <email>` and write `%LOCALAPPDATA%\hesper\auth.json`
(or `~/.hesper/auth.json`). Test with an email that has never signed in before —
an existing session can mask a broken sign-up path.
